# Measure first, then make auto_review agentic

By November 2026 the leading AI pull-request reviewers have settled on the same design: an **agentic investigator** that pulls repository context with tools, a **separate verification or judge stage**, aggressive **noise suppression** (category filters, comment caps, P0/P1-only output), and **outcome telemetry** (did the author change code in response?) that drives feedback-trained suppression and learned rules. auto_review already has the skeleton of this design (self-heal, a cheap or agentic verifier, a severity floor, a learnings store, CI-gated triggers). Its largest gaps are not exotic features. It does not measure whether its comments get acted on. It does not let the generation pass use the read-only tools that already exist for the verifier. Its learnings are not scoped per repository and do not learn from dismissals. It reads `.auto_review.yaml` for reviews from the PR's own head commit. The highest-value roadmap is therefore: instrument the addressed rate and widen the benchmark; fix the trust and scoping defects; cut noise with caps, category filters and suggestion blocks; then move to agentic generation, feedback-trained suppression, linked-issue grounding and custom pre-merge checks. Several high-profile vendor features should be skipped explicitly: bundled linters and code execution inside the review runtime, docstring generation (CodeRabbit retired it on Nov 11, 2026), fix-CI and merge-conflict agents, IDE extensions, and GitLab/Bitbucket support. They either conflict with auto_review's security design or have weak evidence of value. The market gap is real. None of Greptile, Graphite or Cursor Bugbot supports Forgejo. Google and AWS are leaving the hosted GitHub-reviewer market. Kodus, the closest open-source peer, keeps learnings out of its self-hosted edition.

## Four mechanisms separate 2026 leaders from 2024-era diff bots

The clearest public account of what moves quality comes from Cursor. Bugbot started in July 2025 as **eight parallel passes over randomized diff orderings with majority voting**, a validator model and deduplication against earlier runs. In fall 2025 it switched to a single fully agentic design that calls tools and decides where to dig, which Cursor says produced its *largest* gains. Across 40 major experiments the resolution rate rose from **52% to over 70%**, and resolved bugs per PR rose from about 0.2 to about 0.5 ([Cursor](https://cursor.com/blog/building-bugbot)). It reached **78%** in April 2026, when learned rules shipped ([Cursor changelog](https://cursor.com/changelog/04-08-26)). Two details matter for auto_review. The agentic version was "too cautious", so prompts were made *more* aggressive. And tool design had an outsized effect on behavior. OpenAI reached the same conclusion from the model side: a reviewer with repo-wide tools and code execution produced fewer false alarms than a diff-only one, and OpenAI chose precision over recall on purpose, modelling stylistic comments as potentially *negative* utility. **52.7%** of its comments were addressed with a code change ([OpenAI Alignment](https://alignment.openai.com/scaling-code-verification/)).

The second mechanism is parallel, narrowly scoped investigation. Greptile went from a single agentic loop (v3) to a "swarm" in which each agent chases one bug hypothesis (v5, Aug 2026). An A/B test on more than 1M PRs raised the share of comments authors addressed from **52% to 66%** ([Greptile v5](https://www.greptile.com/blog/greptile-v5)). Sentry's published pipeline caps drafts at **three hypotheses per PR**, verifies each in its own concurrent agent, and discards predictions with low 0–1 confidence or severity ([Sentry](https://blog.sentry.io/building-a-code-review-system-that-uses-prod-data-to-predict-bugs)). Anthropic's managed Code Review documents the same shape: Find (parallel agents), Verify, Rank, Post ([Claude Code docs](https://code.claude.com/docs/en/code-review)). GitHub turned Copilot's cheapest "Lite" tier into an ensemble of agents. Compared with a single agent, that raised **addressed high-severity comments per review by 47%** and lowered cost by 8% ([GitHub changelog](https://github.blog/changelog/2026-09-11-auto-resolution-and-analysis-updates-in-copilot-code-review/)).

The third mechanism is suppression, which matters more than generation. Greptile's 2024 baseline was **79% nits**. Prompt engineering cut critical comments along with nits, few-shot examples made output worse, and LLM self-rated 1–10 severity scores were "nearly random". What worked was a per-team vector store of past comments that blocks a new comment when it closely resembles at least three downvoted ones. That raised the address rate from about **19% to over 55% within two weeks** ([Greptile](https://greptile.com/blog/make-llms-shut-up)). Graphite filters on a 2x2: post only what the LLM catches reliably *and* humans want, and suppress technically correct but unwanted categories such as "add tests" or "extract function" ([AI Engineer talk](https://ai.engineer/talks/ai-powered-entomology-lessons-from-millions-of-ai-code-reviews)). Independent research supports this. An MSR '26 study found **12 of 13 review agents below 60% signal**, and PRs reviewed only by an agent merged at 45.2% versus 68.4% for human-reviewed PRs ([arXiv 2604.03196](https://arxiv.org/html/2604.03196v1)). A 7,416-comment study ties higher bot comment volume to diluted review quality ([arXiv 2604.24450](https://arxiv.org/html/2604.24450v1)).

The fourth mechanism is outcome measurement. Bugbot uses an LLM at merge to judge which flagged bugs were resolved. Greptile compares a PR's first and last commits. Graphite tracks action rate and explicitly rejects thumbs reactions because **fewer than 4% of users vote** ([AI Engineer talk](https://ai.engineer/talks/ai-powered-entomology-lessons-from-millions-of-ai-code-reviews)). Copilot added Addressed / Won't fix / Incorrect resolution reasons in August 2026 ([GitHub changelog](https://github.blog/changelog/2026-08-27-copilot-code-review-resolution-reasons-and-expanded-capabilities/)). Cursor tracks comments per run alongside resolution rate, so that precision cannot improve simply by saying less ([Cursor](https://cursor.com/blog/building-bugbot)).

Benchmarks are less trustworthy than these production metrics. Every vendor-run benchmark ranks its author first. The Augment run is typical: Augment scores 65/55/59 precision/recall/F, Bugbot 60/41/49 and CodeRabbit 36/43/39 ([Augment](https://www.augmentcode.com/blog/we-benchmarked-7-ai-code-review-tools-on-real-world-prs-here-are-the-results)). The independent Martian Code Review Bench made its online, behaviour-based track the headline because offline gold sets count real but unlisted findings as false positives ([The New Stack](https://thenewstack.io/github-reviewbench-code-review/)). Academic absolute numbers are sobering. The best systems reach about **12% F1 on SWR-Bench** ([arXiv 2509.01494](https://arxiv.org/abs/2509.01494)) and about **one third of known defects on CR-Bench-v2**. CR-Bench-v2 also shows why usefulness alone misleads: Gemini Code Assist scored **78% usefulness but 8.1% known-defect detection** ([arXiv 2611.02566](https://arxiv.org/html/2611.02566v1)). auto_review's 7-fixture bench with precision, recall and a regression gate is a sound base, but it is too small to tune against.

## The market is consolidating, and Forgejo remains unserved

CodeRabbit has grown from a PR bot into an "SDLC agent platform". It now spans CLI, IDE, Slack agents, issue planning, triage, a security deep-scan product and a 150-plus-operation API and MCP server ([CodeRabbit changelog](https://docs.coderabbit.ai/changelog)). Most of that platform is irrelevant to a self-hosted reviewer, but its review core sets the configuration bar. That core includes layered config with path-scoped instructions, ingestion of CLAUDE.md, AGENTS.md and `.cursorrules`, learnings with local or global scope and an approval queue, natural-language pre-merge checks with off/warning/error modes, and quiet/chill/assertive profiles ([CodeRabbit config reference](https://docs.coderabbit.ai/reference/configuration); [pre-merge checks](https://docs.coderabbit.ai/pr-reviews/pre-merge-checks)). Cursor agreed to acquire Graphite in December 2025 ([SiliconANGLE](https://siliconangle.com/2025/12/19/cursor-acquires-ai-code-review-startup-graphite/)). Sonar bought Gitar in May 2026 ([Sonar](https://sonarsource.com/company/press-releases/sonar-acquires-gitar/)). Google ended consumer Gemini Code Assist reviews in July 2026 ([9to5Google](https://9to5google.com/2026/06/17/gemini-cli-code-assist-shutting-down/)). Amazon Q's GitHub reviewer stops taking new installs on Nov 18, 2026 ([GitHub Marketplace](https://github.com/marketplace/amazon-q-developer)). Qodo handed PR-Agent to a community org under Apache 2.0 ([Qodo](https://www.qodo.ai/blog/qodo-is-handing-pr-agent-over-to-the-community/)).

For auto_review the relevant field is narrow. Bugbot supports GitHub, GitLab, Bitbucket, Azure DevOps and Origin, but **not Forgejo** ([Bugbot docs](https://cursor.com/docs/bugbot)). Greptile self-hosts but lists no Forgejo or Gitea support ([Greptile changelog](https://www.greptile.com/docs/changelog)). Kodus is AGPLv3, self-hosted and Forgejo-aware ([GitHub](https://github.com/kodustech/kodus-ai)), but its open-source edition excludes "Kody Learnings" and caps custom rules at 10 ([Kodus docs](https://docs.kodus.io/knowledge_base/en/how-to-self-host-ai-code-review.md)). A Forgejo-first reviewer with fully open, measured learning therefore has room.

Security incidents confirm that auto_review's main architectural choice is right. Kudelski got **remote code execution on CodeRabbit's production review runtime** through a PR-supplied `.rubocop.yml` `require`, which leaked secrets and gave write access to about 1M repositories ([Kudelski](https://kudelskisecurity.com/research/how-we-exploited-coderabbit-from-a-simple-pr-to-rce-and-write-access-on-1m-repositories)). auto_review runs no repo-controlled tools at review time and leaves deterministic linters to CI (ADR-0010/0012), which rules out that class of attack. The 2026 "Ghostcommit" attack hid prompt-injection directives in PNGs. They passed CodeRabbit and Bugbot unflagged and were later executed by coding agents to exfiltrate `.env` files ([CSA](https://labs.cloudsecurityalliance.org/research/csa-research-note-ghostcommit-image-prompt-injection-ai-code/)). Prompt injection through repository content is now a real attack surface for reviewers. auto_review currently loads `.auto_review.yaml` for reviews from the PR head workspace (`crates/ar-orchestrator/src/dispatcher.rs:755` calls `load_repo_config(workspace.path())` on the head checkout). A PR can therefore set `enabled: false`, add `ignored_paths` that cover its own changes, or rewrite `guidelines` to steer its own review. The chat path already does the right thing: `load_repo_config_for_chat` reads from `pr.base.ref_name`, so `override_approvers` is not exposed. Bugbot reads `bugbot.yaml` from the base branch so a PR "can't change its own review settings" ([Bugbot docs](https://cursor.com/docs/bugbot)). Anthropic honours `REVIEW.md` only from a protected default branch ([Claude Code docs](https://code.claude.com/docs/en/code-review-customize.md)).

## Unfinished features and deliberate skips

Several existing features are partial and should be finished before anything new is built. **Learnings are not repo-scoped**, so a correction on one repository steers reviews of every other repository on the same deployment. That is a correctness defect and, on a multi-tenant gateway, a confidentiality defect. The **co-change graph** has code but no wiring, and the docs claim it works. It should be wired into context ranking or the agentic tool set, or deleted, together with the documented-but-unwired LLM triage. The `Inferred` learning source exists but is never written. It should stay dormant until telemetry can show that inferred rules help. The **agentic verifier is opt-in**. Once the benchmark is larger it should be compared against the simple verifier and made the default if it wins. **Suggestion blocks** exist only in `autofix` and `docstring`, although research favours them on every concrete finding. Reviews post a **new review each run** instead of updating a persistent summary, and dedupe relies on the prompt. Four doc/code drifts erode trust: the severity floor (docs say Note, code says Warning), the USER-GUIDE claim that the bot cannot approve, the co-change/triage claims, and a system prompt that says "Forgejo PR" on GitHub. Each takes about an hour to fix. Finally, the review path should read `.auto_review.yaml` from the base branch, as the chat path already does.

The skips are deliberate, not omissions. The most-marketed CodeRabbit features are its 59 bundled analyzers and its sandboxed agents that build, run CI and resolve conflicts. Both require executing repository-controlled code, which is the exact class of attack that produced the Kudelski RCE. auto_review's ADR-0010/0012 position (deterministic tools in CI, read-only tools at review time) is a security feature worth stating publicly, not a gap. Execution-based verification (Greptile TREX, Copilot shell tools) is skipped for the same reason. auto_review's equivalent is to consume CI results as context. Docstring generation should be **deprecated**: the category leader retired both the feature and its coverage check on Nov 11, 2026 ([CodeRabbit changelog](https://docs.coderabbit.ai/changelog)). Test generation should get no further investment, given Tusk's reported sunsetting and Graphite's finding that "add tests" comments are unwanted. GitLab, Bitbucket and Azure DevOps stay out of scope. So do IDE extensions, chat-platform agents, PR triage, planning, post-merge actions, diff-reordering UIs and poems. They make CodeRabbit a platform, but they do nothing for review quality and they spread a small project's maintenance budget thin.

One steelman deserves an answer. CodeRabbit argues that agentic shell exploration in a sandbox beats pre-indexed RAG, and it builds a fresh structural graph per review instead of relying on embeddings ([The AI Engineer](https://theaiengineer.substack.com/p/how-coderabbit-actually-works), secondhand). Taken seriously, this suggests auto_review's embedding index matters less than giving the generator good read-only tools (read, grep, find-symbol, find-callers). The recommendation is to keep embeddings for learnings and suppression, where the evidence is strongest, and to let tools carry code context.

## Conclusion

The research changes the framing of "CodeRabbit parity". Feature counts are the wrong target. CodeRabbit's breadth is mostly platform sprawl, and its most dangerous capability, running repository tools at review time, is one auto_review rightly refuses. The vendors whose quality improved measurably in 2025–2026 (Cursor, Greptile, OpenAI, GitHub) improved through a loop: measure whether authors act on comments, suppress what they ignore, then give the reviewer more agency to find what matters. auto_review can run that whole loop with components it already has, namely the read-only workspace tools, the embedding store, the chat poller, the bench and the Prometheus pipeline. It lacks the wiring and the outcome metric.

Two items are urgent rather than strategic. Review configuration should be read from the base branch, and learnings should be repo-scoped. Both are small fixes for real defects, and both are prerequisites for the learning features that would distinguish auto_review from Kodus and the single-pass Forgejo bots. If those land with outcome telemetry, auto_review can publish its own addressed-rate numbers. No other self-hosted Forgejo reviewer does that today, and it would make it the credible open alternative in a market that commercial vendors are consolidating away from self-hosters.
